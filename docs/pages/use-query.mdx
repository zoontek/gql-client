# useQuery

## `useQuery(query, variables)`

Runs `query` with `variables` against the `Client` from the nearest `ClientProvider`, and keeps the result in sync with the cache.

```tsx
import { useQuery } from "@zoontek/gql-client";
import { graphql } from "./gql";

const FilmDetailsQuery = graphql(`
  query FilmDetails($filmId: ID!) {
    film(id: $filmId) {
      id
      title
      director
      releaseDate
    }
  }
`);

const FilmDetails = ({ filmId }: { filmId: string }) => {
  const [{ data, fetching }] = useQuery(FilmDetailsQuery, { filmId });
  const { film } = data;

  return (
    <div style={{ opacity: fetching ? 0.5 : 1 }}>
      {film == null ? (
        <div>No film</div>
      ) : (
        <>
          <h1>{film.title}</h1>
          <div>Director: {film.director}</div>
        </>
      )}
    </div>
  );
};
```

### Params

- `query`: your query document node.
- `variables`: your query variables.

### Returns

A `[state, actions]` tuple, like `useState`:

| | |
| --- | --- |
| `state.data` | the query result. |
| `state.fetching` | `boolean`, `true` while a request for the current variables is in flight. `data` may still hold the previous result while this is `true`, so a loading UI is optional. |
| `actions.setVariables(variables)` | patches the variables in place, without a full reload. Used for pagination, see [Pagination](/pagination). |

### Suspense

`useQuery` suspends the first time it's called for a given set of variables, and resumes once the result arrives. Render it under a `Suspense` boundary, as shown in [Getting started](/#4-wrap-queries-in-suspense).

A later call to `setVariables` doesn't suspend again: the component keeps rendering with the previous result and `fetching: true` until the new one lands.

### Errors

A failed request throws during render, to be caught by the nearest `ErrorBoundary`. See [Errors](/errors) for what `ClientError` exposes.

### Reloading

Passing a new, structurally different `variables` object (not deeply equal to the previous one) reloads the query from scratch: it suspends again, and any pending `setVariables` patch is discarded.
