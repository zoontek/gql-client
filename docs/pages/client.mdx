# Client [Configuration and methods.]

```ts title="src/client.ts"
import { Client } from "@zoontek/gql-client";
import schemaConfig from "./schemaConfig.json";

export const client = new Client({
  url: "https://api.example.com/graphql",
  schemaConfig,
});
```

## Configuration

```ts
type RequestPayload = {
  operationName: string | undefined;
  query: string;
  variables: AnyVariables;
};

type ClientConfig = {
  url: string;
  schemaConfig: SchemaConfig;
  requestOptions?:
    | RequestOptions
    | ((payload: RequestPayload) => RequestOptions | Promise<RequestOptions>);
};

new Client(config: ClientConfig): Client;
```

| Option           | Description                                                                                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`            | Required. The GraphQL endpoint. Every request is sent here as an HTTP `POST`.                                                                                  |
| `schemaConfig`   | Required. The interface-to-types map generated by [`gql-schema-config`](/#2-generate-the-schema-config).                                                       |
| `requestOptions` | Optional. Options merged into every request. Pass a function (sync or async) to compute them per request, see [Authentication](/authentication). Fields below. |

```ts
type RequestOptions = {
  credentials?: RequestCredentials;
  headers?: Record<string, string>;
  integrity?: string;
  keepalive?: boolean;
  mode?: RequestMode;
  timeout?: number;
};
```

| Field         | Description                                                                          |
| ------------- | ------------------------------------------------------------------------------------ |
| `headers`     | Extra HTTP headers merged into every request.                                        |
| `timeout`     | Request timeout in milliseconds. Defaults to `10_000`. Set `Infinity` to disable it. |
| `credentials` | Passed to `fetch` as `credentials`.                                                  |
| `mode`        | Passed to `fetch` as `mode`.                                                         |
| `integrity`   | Passed to `fetch` as `integrity`.                                                    |
| `keepalive`   | Passed to `fetch` as `keepalive`.                                                    |

If the `requestOptions` function throws or rejects, the request fails with a [`ClientError`](/errors) whose `reason` is `"options"`.

## Methods

Most apps only need the hooks. These methods are what the hooks call under the hood; use them directly for one-off requests outside a component, or for the [SSR](/server-side-rendering) and [refetch](/refetching) flows.

### query

```ts
query<Data, Variables>(
  document: TypedDocumentNode<Data, Variables>,
  variables: Variables,
  options?: { refresh?: boolean },
): Promise<Data>;
```

Sends `document`, writes the response into the cache, and resolves with the response data. Throws a [`ClientError`](/errors) on failure.

Calls for the same document and variables share one promise: a call made while a request is in flight joins it, and a call after success reuses the settled result. Pass `refresh: true` to replace a settled result with a fresh request. A rejected promise is dropped, so the next call retries.

### mutate

```ts
mutate<Data, Variables>(
  document: TypedDocumentNode<Data, Variables>,
  variables: Variables,
  config?: { connectionUpdates?: GetConnectionUpdate<Data, Variables>[] },
): Promise<Data>;
```

Same as `query`, but never deduplicated, and accepts [connection updates](/mutations#updating-connections).

### refetch

```ts
refetch(): Promise<void>;
```

Re-sends every mounted query and writes the fresh responses into the cache. Resolves once every request has settled; never rejects. See [Refetching](/refetching).

### purge

```ts
purge(): void;
```

Drops every cache entry, then notifies all subscribers so mounted queries fetch fresh data. Useful on logout.

### extract

```ts
extract(): string;
```

Serializes the cache to script-safe JSON text (every `<` escaped). See [Server-side rendering](/server-side-rendering).

### restore

```ts
restore(data: SerializedCache | string): void;
```

Replaces the cache content with data produced by `extract()`, then notifies subscribers. Call it before rendering, on a client that hasn't fetched anything yet.
