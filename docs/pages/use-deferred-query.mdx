# useDeferredQuery [Run a query on demand instead of automatically on render.]

Like `useQuery`, but the request isn't sent automatically: call the returned function to send it.

## Basic usage

```tsx title="src/FilmSearch.tsx"
import { useState } from "react";
import { useDeferredQuery } from "@zoontek/gql-client";
import { graphql } from "./gql";

const SearchFilmsQuery = graphql(`
  query SearchFilms($title: String!) {
    films(title: $title) {
      id
      title
    }
  }
`);

const FilmSearch = () => {
  const [state, searchFilms] = useDeferredQuery(SearchFilmsQuery);
  const [title, setTitle] = useState("");

  const onSubmit = (event: React.FormEvent) => {
    event.preventDefault();
    searchFilms({ title });
  };

  return (
    <div>
      <form onSubmit={onSubmit}>
        <input
          value={title}
          onChange={(event) => setTitle(event.target.value)}
        />
        <button type="submit" disabled={state.fetching}>
          Search
        </button>
      </form>

      {state.status === "success" && (
        <ul>
          {state.data.films.map((film) => (
            <li key={film.id}>{film.title}</li>
          ))}
        </ul>
      )}

      {state.status === "error" && <div>{state.error.message}</div>}
    </div>
  );
};
```

## Signature

```ts
type DeferredQueryState<Data> =
  | { fetching: false; status: "idle" }
  | { fetching: true; status: "loading" }
  | { fetching: false; status: "success"; data: Data }
  | { fetching: false; status: "error"; error: ClientError };

type DeferredQuery<Data, Variables> = readonly [
  DeferredQueryState<Data>,
  (variables: Variables) => Promise<Data>,
];

function useDeferredQuery<Data, Variables>(
  query: TypedDocumentNode<Data, Variables>,
): DeferredQuery<Data, Variables>;
```

## Params

| Param   | Type                                 | Description               |
| ------- | ------------------------------------ | ------------------------- |
| `query` | `TypedDocumentNode<Data, Variables>` | Your query document node. |

## Returns

A `[state, query]` tuple:

| Field              | Type                                      | Description                                                                                                                                                                                                                                                          |
| ------------------ | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `query(variables)` | `(variables: Variables) => Promise<Data>` | Sends `query` with `variables`, writes the response into the cache, and updates `state` as it settles. Returns a promise resolving with the response data. If called again before the previous call resolves, only the latest call's result is reflected in `state`. |
| `state`            | `DeferredQueryState<Data>`                | Narrowed on `status`, see the table below.                                                                                                                                                                                                                           |

| Status      | Shape                                          |
| ----------- | ---------------------------------------------- |
| `"idle"`    | `{ status: "idle", fetching: false }`          |
| `"loading"` | `{ status: "loading", fetching: true }`        |
| `"success"` | `{ status: "success", fetching: false, data }` |
| `"error"`   | `{ status: "error", fetching: false, error }`  |

## `useQuery` vs `useDeferredQuery`

`useQuery` suspends and runs as soon as it's called with a set of variables, so it fits data a component needs to render. `useDeferredQuery` doesn't run until you call the returned function, so it fits data triggered by a user action, such as a search form.

Since `query` writes its response into the cache, the same as `useQuery`, other components reading the same query and variables pick up the result too.
